# 采集与数据质量

起点采集使用现有 patchright 浏览器。四个榜单先逐分类保存名单，再按书籍 ID 合并成一个详情队列。这样补字数、作者、简介时受阻，不会让已经成功抓到的其他榜单名单丢失。同一本书在多个榜单或分类中出现，详情只补一次并回填所有记录。

## 缓存和请求预算

在项目根目录的 `.env` 设置以下选项，也可通过进程环境变量覆盖：

| 选项 | 默认值 | 行为 |
| --- | --- | --- |
| `QD_DETAIL_TTL_HOURS` | `24` | 字数采集后经过多少小时进入刷新队列；`0` 每次刷新 |
| `QD_DETAIL_MAX_REQUESTS` | `0` | 一次起点运行的详情页导航总预算，含失败重试；`0` 不设上限 |
| `QD_COOLDOWN_SECONDS` | `3600` | 站点拦截后冷却秒数，最低 60；服务器要求更久时采用更长的等待时间 |
| `QD_HEADED` | `0` | `1` 临时打开浏览器窗口排查 |

缺字数的书优先补全，其后刷新最早采集的记录。字数尚在有效期内，但作者或简介缺失，也会进入详情队列。预算耗尽时保存结果并结束详情阶段；之后再运行可继续补全。同日已完成的分类名单沿用断点记录，不会因此重新请求。

缓存只减少有效期内重复请求。每天恰好间隔 24 小时运行时，前一天字数可能已经过期，不能据此承诺每日请求量必然大幅下降。延长 TTL 可减少刷新，但会展示更旧的字数；实际取舍应根据页面标注的时间与本地请求统计判断。

`.runtime/qidian.sqlite3` 保存详情和冷却。缓存保留最近 30 天，最多 5000 本。首次运行没有持久化缓存；此后的成功采集逐步填充缓存。历史任务状态中只有日期的旧字数只标注“采集日”，不伪造小时和分钟。

## 失败、冷却和任务锁

HTTP 403、429、503 会暂停起点请求；`Retry-After` 支持秒数和 HTTP 日期。连续三本详情验证码、连续三次分类验证码也会暂停；三江单页验证码直接暂停。浏览器明确报告 `ERR_INTERNET_DISCONNECTED` 或 `ERR_NETWORK_ACCESS_DENIED` 时，起点立即停止当前平台、保留进度并冷却五分钟；番茄也会停止当前平台并返回失败，不逐分类或逐榜重试这些错误。冷却状态跨进程保存，下次启动先检查，未到期就退出，不启动浏览器。网络权限被拒需要处理运行环境权限；等待五分钟不会自动解除限制。

| 起点直接运行退出码 | 含义 |
| --- | --- |
| `0` | 名单达到完整性要求；详情预算耗尽仍可为 0，详情是否齐全应检查质量字段 |
| `1` | 有榜单未达到完整性要求，或出现其他未处理异常 |
| `2` | 已有同类任务运行 |
| `75` | 正在冷却，或本次触发站点拦截、断网或网络访问被拒 |

`run_all.py` 汇总子任务失败并返回非零，不直接透传上述各个平台的退出码。手动单平台入口、调度入口、构建入口都有限制重复执行的操作系统锁；构建和创作建议重生成共享锁。锁文件保留不代表任务仍在运行，进程退出后锁由系统释放。不要删除运行中的锁文件。

`.runtime/qidian_status.json` 记录最近一次运行的榜单/详情导航次数、缓存命中书数、详情失败数、未完整榜单和剩余冷却。导航次数不等于浏览器发出的全部网络请求数。此文件会被后一次运行覆盖，历史过程日志仍在 `logs/`。

## 网络被拒后的恢复顺序（Windows）

先停止全量重跑。使用项目已安装依赖的虚拟环境，不必因网络权限报错重复安装 Python 或浏览器。在允许联网的 PowerShell 中切换到项目目录，运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 smoke_qidian_patchright.py --rank-only
```

这次只导航一页起点榜单，检查身份和封面地址是否能解析，不请求书籍详情，也不改写 `data/` 或 `api/`。页面仍可能发出脚本等子资源请求。报告写入 `probe_out/live_qidian/`，沿用起点任务锁和持久化冷却。

- 若交互终端检查通过、自动化运行仍报 `ERR_NETWORK_ACCESS_DENIED`，优先核对自动化进程的网络权限和执行账户；这表明运行上下文可能有差异。
- 若交互终端也出现同一错误，检查防火墙、安全软件和代理策略对实际 Chrome/Chromium 进程的访问规则。按环境管理要求授予所需访问，不需要关闭整个防火墙。
- 若得到 HTTP 403/429/503 或验证码，按站点限制和冷却处理；它与浏览器网络权限被拒是不同的失败原因。
- 若能够访问但解析结果为空，需要检查站点页面结构。单页检查未通过时不要扩大为全量采集。

单页检查通过后，运行不带参数的 `smoke_qidian_patchright.py`，再验证一页榜单和首本详情；两项通过后才运行 `run_all.py --platform qidian --no-ai`。起点完成后分别验证其余平台，最后再启用全平台或定时任务。上述脚本都使用同一个 `.venv\Scripts\python.exe`。

`--no-ai` 只关闭 AI，仍会抓取网站。只想更新已有看板时使用 `run_all.py --no-scrape --no-ai`。失败运行留下的空快照和断点无需手动删除：构建会跳过不完整快照，抓取重跑会重试未完成分类。保留最近有效数据，不能把旧数据日期改成今天。强制结束进程可能来不及更新状态文件，诊断时同时核对状态时间和运行日志。

## 数据字段和展示

新起点快照区分排名名单和详情状态：

- `quality.rank_status`：所有配置分类完成才为 `complete`，否则为 `partial`。旧快照没有此状态时为 `unknown`，仍按已有分类/条目阈值判断可用性。
- `quality.detail_status`：指标、作者和简介齐全时为 `complete`；否则为 `partial`。
- `metrics_available`、`metrics_missing`、`metric_coverage`：各分类行的有效指标数、缺失数和覆盖率；同一本书在多个分类出现时按各行计数。
- `metrics_cached`、`metrics_observed_unknown`、`authors_missing`、`intros_missing`：缓存使用与缺失情况。
- `collected_at`：本快照最近保存时间，不能解释为每个字数的采集时间。
- 书籍的 `word_count_observed_at`、`word_count_source`：字数实际采集时间和来源（`rank`/`detail`/`cache`/`legacy`/`unknown`）。跨日复用保留原时间，未刷新成功不更新成当天。

构建将质量信息保留在 latest 和各级 API 中。完整排名可以带着未补齐的详情构建；明确未完成的名单不会仅因数量超过阈值而当作完整榜。看板会提示详情缺失，书卡与排名/竞品导出保留字数时间说明。竞品指标分布记录 `sample_size` 和 `ranked_books`；缺失指标不计作 0 参与均值，全部缺失时不生成虚假的均值。

“榜单样本分析”来自前 20 本书名和简介的关键词统计，不是实际读者调查；不同平台的在读人数、字数、积分也不是同一种热度单位。

## 仅刷新已有快照

`python run_all.py --no-scrape --no-ai --platform qidian` 只重建起点聚合，不请求小说网站或 AI。省略 `--platform qidian` 可重建所有平台；单榜可用 `python scripts/build_latest.py --rank-type qidian_hotsales --no-ai`。

此操作更新看板、API 和规则分析，保留已有创作建议；不会补造缺失指标或改变原始快照。旧 AI 建议保留原有日期，不能解释为此次生成的新建议。

## 历史保留与清理

`python scripts/cleanup_task_states.py --keep-days 30 --dry-run` 预览清理范围，去掉 `--dry-run` 执行。清理先更新日期索引，再删除旧快照和状态文件；当前 latest 引用的快照即使超过保留期也会留下，以便看板和发布包继续使用。其他索引元数据保留，已有缺失历史引用会被剔除。

若 latest 所需的快照已经丢失、索引损坏或其他采集/构建正在运行，清理会停止并返回非零；先修复数据或等待任务结束。索引写入失败时不删除快照，文件删除失败则保留未删除文件并报告失败，可随后重试。趋势与作者分析文件不在此清理范围内；静态打包只复制日期索引实际引用的历史。

## 离线验收

```bash
python -m unittest discover -s tests -v
node --test tests/frontend_quality.test.cjs
python smoke_ai_client.py
python scripts/check_config_sync.py
python -m ruff check .
```

Python 测试使用临时目录与模拟页面，覆盖名单优先、共享详情队列、TTL、预算、跨进程冷却、任务锁、质量信息构建、零有效样本、API 旧分类清理、分页失败续传和文件保存失败等行为。Node.js 18+ 测试验证质量提示与导出。以上命令不抓取真实网站、不调用真实 AI，也不重建工作区的真实榜单数据。

真实站点的耗时、成功率与页面兼容性仍需实际运行后根据日志验收。这里的文件锁和原子 JSON 写入不等于整站发布事务；公网部署使用[发布与定时任务](发布与定时任务.md)中的独立发布目录，其他边界见[已知限制](已知限制.md)。
